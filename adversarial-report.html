What this run does not show

  • The attacker is scripted, not independent. These are the attacks A2AWall was built to refuse, written by the same author. A real assessment needs an adversary who did not read the source.
  • The agents are deterministic. No model is in the loop, so the prompt-injection case tests the trusted context boundary's classification, not a model's resistance to persuasion.
  • The tool sandbox is a policy evaluator, not isolation. Tools run in the gateway process. The SSRF and traversal cases were refused before any I/O, which is not the same as containing a tool that misbehaves.
  • Lexical checks only. Host and path allowlists are evaluated as text. A hostname that resolves to a blocked address, or a symlink out of an allowed directory, is the responsibility of the component performing the I/O.
  • Single process, in-memory state. Task ownership is known only to the instance that admitted the request. A multi-instance deployment needs a shared store.
  • Credentials are static bearer tokens. A signed-token verifier is an extension point, not something shipped here.
